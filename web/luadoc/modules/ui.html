Module ui

Building what an app draws.

render returns a tree of nodes made with these functions. Each takes a table: its children (or, for text and image, its content) in order, and its options by name. A single value also works: ui.text "hello".

A nil or false child is skipped, so a child can be conditional:

ui.column {
  ui.text { "always" },
  show_more and ui.text { "sometimes" } or nil,
}

Containers place their children one after another along their axis. Children that set grow share the space left over; otherwise justify places them. Across the axis, align places each child, stretching it to the full width (or height) by default.

Everything is drawn in pure black and white: text is crisp, images are dithered.

column(t)
Children one under another.

Parameters:

  • t The children, then these options:
    • gap number Pixels between children. (default 6)
    • align string Across: "start", "center", "end" or "stretch". (default "stretch")

    Node

Usage:

    ui.column { justify = "center", ui.text "a", ui.text "b" }

text(t)
Text.

Styles: small 16 px, body 22 px (the default), label 16 px bold, title 26 px bold, large 44 px bold, huge 96 px bold. A size is the height of a line, in pixels, in every font. Accents on capitals and low descenders may reach a little above or below the line.

Fonts: sans (Noto Sans, the default), serif (Noto Serif), mono (Noto Sans Mono, every character the same width, for columns of numbers and times) and overpass (Overpass). Each has regular and bold; only serif has italic, and the others ignore it.

A character a font lacks is drawn from Noto Sans, and failing that from DejaVu Sans, which has most symbols: ● ○ ✓ ✗ ▶ ★ ━ → ← ↑ ↓ ☀ ☁ ☂ and many more. A character no font has (most emoji, Chinese and Japanese) shows as an empty box; the developer API's layout report and measure name such characters. Text is put in Unicode's composed form first, so a letter followed by a separate accent is drawn as the accented letter.

Text is drawn crisp: each pixel is black or white by how much of it the letter covers. With smooth, the edges are dithered instead, which softens the curves of large text (about 60 px and up) but makes small text grainy.

Parameters:

  • t The text (a string or a number), then options:
    • style string One of the styles above. (default "body")
    • size number A size in pixels instead of the style's. (optional)
    • bold bool Bold or not, instead of the style's. (optional)
    • font string "sans", "serif", "mono" or "overpass". (default "sans")
    • italic bool Italic, for serif. (default false)
    • smooth bool Dither the edges, for large text. (default false)
    • fit string "shrink": use the largest size, from the style's (or size) down to min_size, at which the text fits its space without being cut: no "…", no lines left out, no words broken. If none fits, min_size, cut as usual. (optional)
    • min_size number The smallest size fit = "shrink" may use. (default 10)
    • wrap bool Break into lines to fit the width. Without it, a line that doesn't fit ends in "…". Newlines always break. (default false)
    • max_lines int At most this many lines; the last ends in "…" if cut. (optional)
    • align string "left", "center" or "right". (default "left")

Returns:

    Node

Usage:

  • ui.text { "A long forecast for the week…", wrap = true, max_lines = 3 }
  • ui.text { data.race_name, style = "huge", fit = "shrink", min_size = 24 }
  • ui.text { "08:00", font = "mono", bold = true }
image(t)
An image, scaled to its space and dithered to black and white.

PNG, JPEG, GIF and WebP work. Transparent areas become white.

Parameters:

  • t The source, then options. The source is a reference from globals.blob, or, for built-in apps only, a file in the app's directory.
    • fit string "contain" shows all of it; "cover" fills the space and crops the edges. (default "contain")
    • dither bool Dither for photos; turn off for line art and text. (default true)

Returns:

    Node

Usage:

    ui.image { data.photo, fit = "cover", grow = 1 }
measure(node[, max_w[, max_h]])
The size a node would take, and whether it fits, before drawing it.

Use it to decide what fits instead of guessing at letter widths. fits and cut come from laying the node out in the space given exactly as a render would, so they agree with what is drawn: a node given w × h (or, with no limits, needed_w × needed_h) is drawn with nothing cut. Text with fit = "shrink" is measured at its full size.

Parameters:

  • node Node or string A node made with these functions, or a string (as body text).
  • max_w number The width available: wrapping text breaks to fit it. Unlimited if left out. (optional)
  • max_h number The height available. Unlimited if left out. (optional)

Returns:

    table

    In whole pixels:

    • w, h: the size it takes within the limits (what a column or row would give it);
    • needed_w: the width it would take with no limit (for wrapping text, one long line);
    • needed_h: the height it needs at max_w;
    • fits: whether it fits the limits with nothing cut;
    • cut: why not, as in the developer API's layout report (too_wide, max_lines, too_tall, word_split, no_space, overflow; and missing_glyph, which doesn't stop it fitting);
    • missing: characters no font has, if any;
    • for text, lines and line_height.

Usage:

  • local title = ui.text { data.name, style = "large", wrap = true }
local m = ui.measure(title, slot.w)
local room_left = slot.h - m.h
  • -- Show the table only if it fits beside the map:
 if ui.measure(timetable, slot.w - 200, room_left).fits then ... end
  • -- The widest label, to size a column:
local w = 0
for _, s in ipairs(sessions) do w = math.max(w, ui.measure(s.label).w) end
